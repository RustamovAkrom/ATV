# 📚 Документация моделей базы данных

## 1. 🏗️ Основные модели (Core Models)

### `Asset` - АКТВ (основной актив)
**Назначение:** Центральная сущность системы - техническое средство (компьютер, камера, радиостанция и т.д.)

**Основные поля:**
- `name` - название актива
- `serial_number` - серийный/инвентарный номер
- `status` - состояние (активен/назначен/в ремонте/архивирован)
- `owner_id` - текущий владелец (ответственный)
- `region_id` - регион (вилоят)
- `service_id` - служба (хизмат)

**Для чего используется:**
- Учёт всех технических средств
- Отслеживание текущего состояния и местоположения
- История всех операций с активом

**Как использовать:**
```python
# Создать актив
asset = await asset_service.create(data, actor)

# Сменить статус
await asset_service.change_status(asset_id, new_status, actor)
```

---

### `AssetModel` - Модель актива
**Назначение:** Справочник моделей техники

**Основные поля:**
- `name` - название модели
- `manufacturer_id` - производитель
- `category_id` - категория
- `lifetime_years` - нормативный срок службы (лет)
- `warranty_months` - гарантия (месяцев)

**Для чего используется:**
- Группировка однотипной техники
- Расчёт износа и прогнозирование замены

---

### `Manufacturer` - Производитель
**Назначение:** Справочник производителей техники

**Для чего используется:**
- Анализ надёжности по производителям
- Планирование закупок

---

## 2. 🔄 Модели движения и назначения

### `AssetAssignment` - Назначение актива
**Назначение:** Учёт закрепления техники за сотрудниками

**Основные поля:**
- `asset_id` - актив
- `user_id` - сотрудник
- `assigned_at` - дата назначения
- `unassigned_at` - дата освобождения

**Для чего используется:**
- Кто сейчас отвечает за технику
- История назначений
- Расчёт нагрузки на сотрудников

**Как использовать:**
```python
# Назначить актив сотруднику
await assignment_service.assign_asset(asset_id, user_id, actor)

# Освободить актив
await assignment_service.unassign_asset(asset_id, user_id, actor)
```

---

### `AssetTransfer` - Перемещение актива
**Назначение:** Учёт перемещений техники между складами/службами

**Основные поля:**
- `from_warehouse_id` / `to_warehouse_id` - откуда/куда на склад
- `from_service_id` / `to_service_id` - откуда/куда в службу
- `status` - статус (ожидает/выполнен/отменён)
- `comment` - комментарий

**Для чего используется:**
- Треккинг местоположения
- Согласование перемещений (через approval)

---

## 3. 🔧 Модели технического обслуживания

### `Repair` - Ремонт
**Назначение:** Учёт всех ремонтов и неисправностей

**Основные поля:**
- `asset_id` - актив
- `status` - статус ремонта (заявлен/в работе/завершён/отменён)
- `description` - описание проблемы
- `labor_cost` - стоимость работ

**Для чего используется:**
- Статистика поломок
- Расчёт затрат на ремонт
- Выявление ненадёжной техники

---

### `RepairPart` - Запчасти для ремонта
**Назначение:** Учёт использованных запчастей при ремонте

**Основные поля:**
- `part_name` - название запчасти
- `quantity` - количество
- `unit_price` - цена за единицу

**Для чего используется:**
- Детальный учёт затрат на ремонт
- Анализ наиболее часто заменяемых деталей

---

### `AssetMaintenance` - Техническое обслуживание (НОВОЕ!)
**Назначение:** Учёт планового технического обслуживания

**Основные поля:**
- `maintenance_type` - тип обслуживания
- `performed_at` - дата проведения
- `issues_found` - выявленные проблемы
- `performed_by_id` - кто проводил

**Для чего используется:**
- Своевременное обслуживание техники
- Продление срока службы
- Документирование профилактических работ

---

## 4. 📦 Модели комплектации

### `AssetComponent` - Комплектующие актива (НОВОЕ!)
**Назначение:** Учёт того, из каких частей состоит актив

**Основные поля:**
- `name` - название компонента
- `serial_number` - серийный номер компонента
- `quantity` - количество

**Для чего используется:**
- Формуляр (паспорт) актива
- При приёме/списании проверка комплектности
- Замена отдельных компонентов

---

### `AssetComponentChange` - Замена компонентов (НОВОЕ!)
**Назначение:** Учёт замены частей актива

**Основные поля:**
- `old_component` - старый компонент
- `new_component` - новый компонент
- `reason` - причина замены
- `changed_by_id` - кто заменил

**Для чего используется:**
- История замен комплектующих
- Анализ наиболее часто заменяемых деталей
- Планирование закупок запчастей

---

## 5. 🏢 Организационная структура

### `Region` - Регион
**Назначение:** Административно-территориальная единица (вилоят → туман → бўлинма)

**Особенности:**
- Иерархическая структура (parent_id)
- Поддержка геоданных (latitude, longitude, geojson)

**Для чего используется:**
- Фильтрация данных по региону
- Анализ по территориальному признаку
- Контроль доступа (пользователь видит только свой регион)

---

### `Service` - Служба/Направление
**Назначение:** Функциональное подразделение (Тергов, Патруль, Алока и т.д.)

**Для чего используется:**
- Фильтрация по службам
- Анализ нагрузки по направлениям

---

## 6. 👤 Пользователи и безопасность

### `User` - Пользователь
**Назначение:** Сотрудник системы

**Важные поля:**
- `role_id` - роль (SUPERADMIN, ADMIN, MODERATOR и т.д.)
- `assigned_region_id` - привязанный регион
- `assigned_service_id` - привязанная служба

**Особенности:**
- Автоматическая генерация `slug` из `login`
- Проверка региона/службы при доступе к данным

---

### `Role` / `Permission` - Роли и права
**Назначение:** Управление доступом (RBAC)

**Как работает:**
- Роли имеют набор разрешений (permissions)
- Пользователь получает права через свою роль
- Возможны индивидуальные права (direct_permissions)

---

## 7. 📄 Документы и изображения

### `Document` - Документ
**Назначение:** Хранение прикреплённых файлов (формуляры, счета, акты)

**Для чего используется:**
- Формуляр (паспорт) актива в электронном виде
- Скан-копии документов
- Согласования и подписи

---

### `DocumentFile` - Файл документа
**Назначение:** Файлы, прикреплённые к документу

**Особенности:**
- Несколько файлов на один документ
- Каскадное удаление при удалении документа

---

### `AssetImage` - Изображение актива
**Назначение:** Фотографии техники

**Особенности:**
- Несколько фото на актив
- Главное фото (is_primary)
- Возможность сортировки (sort_order)

---

## 8. 📊 Учёт и аналитика

### `Expense` - Расход
**Назначение:** Финансовый учёт затрат

**Связи:**
- `asset_id` - расход на актив
- `repair_id` - расход на ремонт
- `region_id` / `service_id` - региональные/служебные расходы

**Для чего используется:**
- Анализ затрат по активам/регионам/службам
- Бюджетирование
- Прогнозирование потребностей

---

### `AuditLog` - Лог аудита
**Назначение:** Запись всех действий в системе

**Для чего используется:**
- Безопасность
- Расследование инцидентов
- Соответствие требованиям (комиссионные проверки)

---

### `Notification` - Уведомление
**Назначение:** Уведомления пользователей

**Каналы доставки:**
- База данных
- WebSocket (реальное время)

---

## 9. ⚙️ Системные модели

### `ApprovalRequest` - Запрос на согласование
**Назначение:** Согласование критических действий

**Что требует согласования:**
- Назначение/перемещение актива
- Архивация/удаление
- Завершение ремонта
- Перемещение на склад

**Как работает:**
1. Пользователь создаёт запрос
2. Согласующие получают уведомление
3. После одобрения действие выполняется автоматически

---

### `RefreshToken` - Токен обновления
**Назначение:** Управление сессиями и JWT токенами

**Для чего используется:**
- Безопасный выход из системы
- Отзыв сессий
- Защита от перехвата токенов

---

## 🎯 Итог: формуляр актива формируется из:

|-----------------|----------------------|
| 1. Комплектация | `AssetComponent` |

| 3. Категория | `AssetClass` |

| 5. Неисправности | `Repair` |

| 9. Проверки | `AuditLog` |
| 10. Документы | `Document` + `AssetImage` |
